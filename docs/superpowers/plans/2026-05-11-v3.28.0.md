## Phase 2 — Concurrency / limit hardening

### Task 2.1: #1143 — make `auth.ip_rate_limited` dampener atomic (TOCTOU)

**Files:**
- Modify: `Simple-PHP-IPAM/lib.php` — `ipam_audit_ip_rate_limited()` (~line 1148; the read-then-insert dampener)
- Test: `tests/IpRateLimitAuditTest.php` (extend — that file exists)
- Read first: `docs/internal/audit-actions.md` (the `auth.ip_rate_limited` row), `tests/AuthRateLimitTest.php`, how `audit()` writes rows. Coordinate with #1159 — land both with the same atomic pattern; if a shared helper or state table makes sense, introduce it here and reuse in 2.2.

- [ ] **Step 1: Understand the current flow**

`ipam_audit_ip_rate_limited()`: SELECT the most-recent matching `audit_log` row for `(action, ip)`, parse its stored `unlock_at` from `details`, `audit()`-INSERT a new dampener row only if no active dampener is in effect. Two concurrent requests can both miss the prior row → both INSERT. The contract is "once per (action, ip) lockout window."

- [ ] **Step 2: Choose the atomic mechanism (DECISION POINT — surface to the user before implementing if option (a))**

`audit_log` is append-only (triggers abort UPDATE/DELETE) with no unique key to lean on, so `INSERT … ON CONFLICT DO NOTHING` won't work there. Options:
  - **(a)** A dedicated tiny state table (like `alert_state` / `rate_limit_buckets`) with `UNIQUE(action, ip)` and an atomic upsert: `INSERT … ON CONFLICT(action, ip) DO UPDATE SET unlock_at = excluded.unlock_at WHERE state.unlock_at < :now` — and only `audit()` when the upsert actually changed/inserted a row. Cleanest "once per window" guarantee. **Requires a migration + 3-schema-file update + data-dictionary regen** (follow `docs/internal/adding-a-migration.md`; run `migration-reviewer` + `multi-engine-schema-parity` subagents). The release was scoped as "no schema migrations" per the issues, so **ask the user first**.
  - **(b)** Wrap the read+insert in a short transaction with engine-appropriate locking — `BEGIN IMMEDIATE` (SQLite) / `SELECT … FOR UPDATE` on a sentinel row (MySQL/Postgres). Portable-ish, no schema change, more fiddly.
  - **(c)** Insert unconditionally; make the dampener *reader* tolerate duplicates. Lowest effort, doesn't satisfy the issue.

  **Default recommendation: (a)** (it's also the shape #1159 wants) — but only if the user okays a new table; otherwise **(b)**.

- [ ] **Step 3: Write the failing/contract test**

Add to `tests/IpRateLimitAuditTest.php`:
```php
public function testDampenerEmitsAtMostOneRowPerWindow(): void
{

    ipam_audit_ip_rate_limited($db, 'login', '203.0.113.7', 900);
    ipam_audit_ip_rate_limited($db, 'login', '203.0.113.7', 900); // second call within the window

        "SELECT COUNT(*) FROM audit_log WHERE action='auth.ip_rate_limited' AND ip='203.0.113.7'"

```
(A single process can't truly race, but this exercises the "second call within the window is a no-op" contract — which the atomic version enforces robustly. Note in the test comment that the cross-process race is covered by the chosen mechanism, not the test.)
