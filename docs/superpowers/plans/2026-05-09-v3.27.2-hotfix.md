## Per-bug commit chain (TDD-first)

Each bug below is one chain: failing test → fix → green test → in-tree gate (`vendor/bin/phpstan`, `phpcs`, `phpunit`, `semgrep`). One commit per logical step; no batched commits.

### Bug 1 — #1124 (P0)

**Failing test (commit 1):** `tests/IPAMBKL1WebauthnRoundTripTest.php` seeds 1 row of `webauthn_credentials` with non-UTF-8 binary in `credential_id` and `public_key`, dumps via `ipam_backup_logical_dump`, reads back via `ipam_restore_logical_dry_run`, asserts:
- footer `total_rows` == reader's `totalRows` (no off-by-N).
- footer `checksum_sha256` matches reader's recomputed hash.
- per-table count for `webauthn_credentials` == 1.
This test must FAIL on `hotfix/v3.27.2`'s base commit (unmodified main).

**Fix (commit 2):** `Simple-PHP-IPAM/lib/backup.php`
- `ipam_logical_column_kind()`: add an explicit per-table override map. Initially: `webauthn_credentials.credential_id` → `binary`, `webauthn_credentials.public_key` → `binary`.
- Writer's encode site (`lib/backup.php:3058`): replace `(string) json_encode(...)` with a wrapper that throws `RuntimeException` naming the table + row PK on `false`. No more silent drops.

**Green test (commit 3):** rerun — failing test now passes. Add a second test asserting the writer throws (not silently emits) when a fixture row has truly unencodable bytes that no override would catch (defensive guard rail).

**Targeted conformance test (commit 4):** `tests/IPAMBKL1ColumnKindOverrideTest.php` — for each entry in the override map, verify a synthetic row with the override-flagged column holding non-UTF-8 binary round-trips cleanly. Asserts the override map is wired in. (NOT the full v3.28.0 conformance class — that walks every column on every engine; this one only covers the override map's contents to lock #1124's fix in place.)

### Bug 2 — #1120 (OIDC auto-prov password)

**Failing test:** `tests/OidcAutoProvPasswordTest.php` calls the OIDC auto-provision code path with a synthetic claim set, asserts the new `users.password_hash` row equals `'!disabled'` (the documented sentinel) — not a real bcrypt hash. Will fail today.

**Fix:** `Simple-PHP-IPAM/oidc_callback.php` (or wherever the auto-prov INSERT lives). Replace the `password_hash(random_bytes(...), PASSWORD_BCRYPT)` call with the literal sentinel `'!disabled'`. Verify nothing in the lockout-protection model currently depends on the field being a real hash (the model expects the sentinel).

**Green test:** rerun.

### Bug 3 — #1121 (settings toggle wipes input)

**Failing test:** `tests/SettingsToggleNoWipeTest.php` (Playwright-style or PHP unit, depending on whether the wipe is server- or client-side). Loads `settings.php`, types a string in field A, toggles boolean B, asserts field A's value persists.

**Fix:** `Simple-PHP-IPAM/settings.php` — separate the boolean-toggle handler path from the group-form save path so toggling doesn't trigger a full-form re-render that drops unsaved string input.

**Green test:** rerun.

### Bug 4 — #1122 (MFA-disable lockout)

**Failing test:** `tests/MfaDisableLockoutGuardTest.php` simulates a user with exactly one enrolled step-up method (TOTP, say), invokes the disable handler, asserts it returns 409 (or whatever status the handler uses for "would-strand-user") rather than allowing the disable.

**Fix:** add precondition guard at every MFA-disable handler — `totp_disable.php`, `email_otp_disable.php`, `passkey_remove.php`. Count user's currently-enrolled methods; if removing the one being targeted would leave zero, refuse with a clear error.

**Green test:** rerun.
