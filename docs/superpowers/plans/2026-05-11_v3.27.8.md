### Bug B + C — Encryption + Type badges

**Root cause:** `Simple-PHP-IPAM/lib/backup_admin_restore.php` controller derives `is_encrypted` from `str_ends_with($name, '.enc')` and `backup_type` from filename suffix. Both ignore DB ground truth in `backup_runs`.

**Fix:** LEFT JOIN `backup_runs` on `(destination_id, filename)`. Use DB values when present; fall back to filename heuristic only for orphan files (Bug D's symptom — clearly labelled).

```php
$runs = []; // map filename -> ['encryption_mode', 'backup_type']
$stmt = $db->prepare(
    "SELECT filename, encryption_mode, backup_type
       FROM backup_runs
      WHERE destination_id = :d AND filename IN (?, ?, ...)"
);
// bind + fetch into $runs map

foreach ($files as &$f) {
    $run = $runs[$f['name']] ?? null;
    if ($run !== null) {
        $f['encryption_mode'] = $run['encryption_mode'];
        $f['backup_type']     = $run['backup_type'];
        $f['is_orphan']       = false;
    } else {
        $f['encryption_mode'] = str_ends_with($f['name'], '.enc') ? 'guess_encrypted' : 'guess_plaintext';
        $f['backup_type']     = str_ends_with($f['name'], '.ipambkl1.gz') ? 'logical' : 'database';
        $f['is_orphan']       = true;
    }
}
```

**UI:** when `is_orphan=true`, render a `<span class="badge badge-warn">no DB record</span>` next to the filename-derived guess so operators understand the badges are inferences not facts.

**Test:** new PHPUnit `tests/RestoreFilenameBadgeTest.php`:
- Seed `backup_runs` rows with mismatched suffixes (encrypted `.enc` with `encryption_mode='unencrypted'`, etc.) → assert controller surfaces DB values
- Seed orphan files (in destination listObjects but no `backup_runs` row) → assert `is_orphan=true` + filename heuristic applied
- Round-trip: write a backup, observe the controller output, assert badges match what was written

### Bug E — Three-state vault status

**Root cause:** Single-helper `ipam_setting('backup_vault_key')` returns the 104-byte envelope; `ipam_vault_unwrap()` throws "authentication failed" because bootstrap key rotated. UI code treats throw as "no envelope" → contradiction with "Stored key" badge that read the envelope directly.

**Fix:** introduce `ipam_vault_status(): array` returning three-state shape:

```php
/**
 * @return array{state:'absent'|'present'|'unreadable', envelope_present:bool, error_message:?string}
 */
function ipam_vault_status(): array {
    $envelope = ipam_setting('backup_vault_key');
    if ($envelope === null || $envelope === '') {
        return ['state' => 'absent', 'envelope_present' => false, 'error_message' => null];
    }
    try {
        ipam_vault_unwrap($envelope);
        return ['state' => 'present', 'envelope_present' => true, 'error_message' => null];
    } catch (RuntimeException $e) {
        error_log('[backup_vault_unwrap] ' . $e->getMessage());
        return [
            'state' => 'unreadable',
            'envelope_present' => true,
            'error_message' => 'Vault envelope exists but is unreadable — bootstrap key has changed since it was written.',
        ];
    }
}
```

**UI affordance (locked decision: diagnostic banner only):**
- `unreadable` state → red danger banner on Destinations tab with the error message + link to a yet-to-be-written `docs/upgrading.md` §vault-recovery section.
- **No** "Replace vault key" action exposed in v3.27.8 — operator must use manual recovery via the docs. Keeps blast radius minimal.

**Test:** `tests/VaultStatusTest.php` — three cases:
1. No envelope → `state='absent'`
2. Valid envelope + matching bootstrap → `state='present'`
3. Envelope wrapped under a different bootstrap key → `state='unreadable'`, `error_message` populated

**Callers to update:** every site that previously called `ipam_setting('backup_vault_key')` for status (not for actual key material) must switch to `ipam_vault_status()`. Per Operating Mode §2: helper ships with ≥1 caller AND every existing site updated, not "land helper, wire callers later."

### Cross-cutting — Drop silent plaintext fallback

**Root cause:** orchestrator's `encryption_mode='stored'` path attempts unwrap → on failure, silently writes plaintext to a `.enc`-suffixed file.

**Fix:**

1. **Preflight check** in `lib/backup.php` orchestrator:
   ```php
   if ($dest['encryption_mode'] === 'stored') {
       $vault = ipam_vault_status();
       if ($vault['state'] !== 'present') {
           audit($db, 'backup.preflight_failed', 'destination', $dest['id'],
                 json_encode(['reason' => 'vault_' . $vault['state']]));
           ipam_record_backup_run_failed($db, $dest['id'], 'vault_' . $vault['state']);
           return ['status' => 'failed', 'reason' => 'vault_' . $vault['state']];
       }
   }
   ```

2. **`backup_runs.status='failed'`** row with populated `error_message` instead of orphan file.

3. **UI surfacing:**
   - Destination card shows danger badge + last failure reason when most recent run is `failed`
   - Backup tab landing page shows banner if any destination has 3+ consecutive failures

4. **Audit verb added:** `backup.preflight_failed` (entity_type `destination`).
   - **Update `docs/internal/audit-actions.md` in the same PR** (per Operating Mode §2 contract-doc rule + locked-in process decision).

**Test:** `tests/BackupOrchestratorPreflightTest.php` — for each `vault_state` (absent/present/unreadable) × `encryption_mode` (unencrypted/stored), assert the right outcome (backup proceeds OR preflight_failed audit + failed run row, never silent plaintext).

**Done-when:** no code path writes plaintext to a `.enc` filename. Every refusal visible via audit + DB row + UI.
