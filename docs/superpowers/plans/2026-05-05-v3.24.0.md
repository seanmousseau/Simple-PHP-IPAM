# v3.24.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the IPAMBKP3 encryption format (three-mode: stored / transitory / unencrypted), introduce the new `backup_vault_key` server secret separate from `app_secret`, add a manual upload-and-restore wizard step with passphrase entry, bundle the v3.21.0 audit cluster of small crypto findings (random_bytes guard, HMAC purpose strings, GCM tag/IV doc), regenerate the data dictionary, and ship the matching docs (configuration.md, backups.md, upgrading.md) and marketing-site card refresh.

**Architecture:** Procedural PHP. New IPAMBKP3 codec lives alongside the existing IPAMBKP1/IPAMBKP2 implementation in `Simple-PHP-IPAM/lib.php` (BACKUP_MAGIC_V2 region, lines ~4313–4640). The dispatcher `backup_decrypt_to_path()` extends to detect IPAMBKP3 magic and delegate. New `backup_encrypt_stream_v3()` and `backup_decrypt_stream_v3()` mirror the IPAMBKP2 single-pass encrypt-then-MAC streaming pattern but with: (1) Argon2id KDF for transitory mode, (2) HKDF over `backup_vault_key` for stored mode, (3) `IPAMBKU1`-tagged passthrough framing for unencrypted mode. Manual restore wizard step lives in `Simple-PHP-IPAM/lib/restore_wizard.php` as a new "Upload" tab beside the existing destination-driven tab. Cron clock-injection seam (T7) lives in `Simple-PHP-IPAM/cron.php` + `lib/backup.php` — testable via override.

**Tech stack:** PHP 8.2 (`sodium_*` Argon2id; openssl AES-256-CTR + HMAC-SHA256; PHP 7.1.2+ `hash_hkdf`). No new Composer dependency. No new vendored frontend asset. `backup_runs.encryption_mode` column already exists in all 3 schemas (shipped v3.21.0).

## Lessons-learned reads applied

- **§5 reference-vector tests for hand-rolled crypto.** v3.19.1 S3 SigV4 incident shipped because canonicalRequest divergence wasn't tested against AWS reference vectors. T6 (#839) MUST include reference-vector tests for every algorithm in IPAMBKP3, not just round-trip self-tests. Vectors required:
  - **HKDF-SHA256:** RFC 5869 Test Case 1 + 2 (already exercised by `ipam_hkdf_sha256` for IPAMBKP2, re-assert for v3 namespace strings).
  - **Argon2id:** RFC 9106 Appendix A.3 reference vector (`password=0101…`, `salt=0202…`, `t=3, m=32, p=4` → known 32-byte tag). PHP 8.2's `sodium_crypto_pwhash` accepts arbitrary parameters via `SODIUM_CRYPTO_PWHASH_ALG_ARGON2ID13`.
  - **AES-256-CTR + HMAC-SHA256:** SP 800-38A AES-256-CTR known-answer; RFC 4231 HMAC-SHA256 vectors; combined encrypt-then-MAC test from RFC 5869's nephew construction (we already lift this from IPAMBKP2 — re-run against v3 with the new HKDF info string).
- **§4 multi-engine gate.** v3.21.1 (HY093) and v3.22.0 (fclose null) both shipped because only SQLite was exercised locally. Crypto code itself is engine-independent, but the `backup_runs` write path (encryption_mode column) is exercised on all three drivers in every encrypt/decrypt run. **Mandatory:** full `bootstrap-app.sh sqlite|mysql|pgsql` pass before push, on every Stream A commit and every release-prep commit.
- **§3 deploy-via-tarball.** Adding `backup_vault_key` to `config.php` means `upgrade.sh` must NOT overwrite the operator's value if the key already exists. Verify the `config.php` merge logic in `upgrade.sh` preserves the new key the same way it preserves `app_secret`.
- **§6 process — explicit per-action approval.** No PR/merge without per-conversation OK. No `git push` without 3-driver pass. No `gh pr merge`. Stop and ask.
- **CHANGELOG known-limitations subsection.** If anything ships partial in v3.24.0, the new `## [3.24.0]` block needs a `### Known limitations` subsection with tracking issue per item. (Not anticipated for v3.24.0 — F17 per-tenant HKDF stays parked at v4.0.0 — but check at release-prep time.)

   - `BACKUP_MAGIC_V3 = 'IPAMBKP3'` (encrypted, two sub-modes via 1-byte mode flag)
   - `BACKUP_MAGIC_UNENC = 'IPAMBKU1'` (unencrypted wrapper, integrity-only)
   - `BACKUP_V3_MODE_STORED = 1`, `BACKUP_V3_MODE_TRANSITORY = 2`

   - [ ] Add constants to lib.php in the existing backup-encryption block.
   - [ ] Add Argon2id helper.

A3. **Implement `backup_encrypt_stream_v3(string $srcPath, string $dstPath, string $mode, ?string $passphrase, string $vaultKey): void`.** Single-pass streaming encrypt-then-MAC mirroring IPAMBKP2 (`backup_encrypt_stream`, lib.php:4380). Header layout:
   ```text
   magic(8)              IPAMBKP3
   mode(1)               STORED=1 | TRANSITORY=2
   argon_time(4)         BE uint32 (only meaningful for TRANSITORY)
   argon_memory(4)       BE uint32 KiB
   argon_parallelism(1)  uint8
   reserved(2)           zero
   argon_salt(16)        random; zero for STORED
   hkdf_salt(16)         random; used in HKDF-Extract
   ctr_iv(16)            random; AES-CTR initial counter block
                          ── header size: 68 bytes
   ciphertext(N)
   hmac_tag(32)          HMAC-SHA256 over (header || ciphertext)
   ```
   Key derivation:
   - **STORED:** `kdf_input = vaultKey`. Argon2id skipped. Derive 64 bytes via `ipam_hkdf_sha256(kdf_input, "ipam-backup-v3:stored:enc-mac", 64, hkdf_salt)`. First 32 = encKey, last 32 = macKey.
   - **TRANSITORY:** `kdf_input = ipam_argon2id_derive(passphrase, argon_salt, argon_time, argon_memory_kib, argon_parallelism, 32)`. Then HKDF as above with info string `"ipam-backup-v3:transitory:enc-mac"`.
   - **UNENCRYPTED** is handled by a separate function (A4).
   - [ ] Implement function.
   - [ ] HMAC purpose-string is included in the info string per #838's `B-P1-13` finding.
   - [ ] `random_bytes` availability is asserted at module load via a one-time `ipam_assert_random_bytes_available()` helper called from `backup_encrypt_stream_v3` and from existing v2 paths (per #838 `B-P1-35`).
   - [ ] Round-trip test: encrypt 1 byte, encrypt 1 MiB, encrypt 100 MiB streaming; assert plaintext bytes match.

A4. **Implement `backup_unencrypted_wrap_stream(string $srcPath, string $dstPath): void` and `backup_unencrypted_unwrap_stream(string $srcPath, string $dstPath): void`.** IPAMBKU1 framing for trusted-local destinations: `magic(8) | sha256(32) | plaintext(N)`. SHA-256 is computed streaming during write; verify on read. No key derivation.
   - [ ] Implement.
   - [ ] Test: tamper with one byte → unwrap fails on hash mismatch.

A5. **Implement `backup_decrypt_stream_v3(string $srcPath, string $dstPath, string $mode, ?string $passphrase, string $vaultKey): void`.** Mirror of A3. Re-derive keys from header-embedded salt + params. Verify HMAC over `header || ciphertext` BEFORE writing the final atomic rename to dst. Write to `${dstPath}.decrypting.<rand>` and rename only after HMAC passes (same TOCTOU-safe pattern as v2's `backup_decrypt_stream`, lib.php:4456).
   - [ ] Implement.

   - [ ] Per #838 `B-P1-40`: the verify path should use double-HMAC compare so error/success run constant time. Implementation: `hash_equals(hash_hmac('sha256', $expected, $verifyKey, true), hash_hmac('sha256', $observed, $verifyKey, true))` where `$verifyKey = ipam_hkdf_sha256(macKey, 'ipam-backup-v3:verify', 32)`. Document in code comment.

For IPAMBKP3, peek mode byte and route to either stored (vaultKey path) or transitory (passphrase path); raise a typed exception on missing key/passphrase that the caller can present cleanly to the operator.
