# v3.31.0 — Settings encrypt-at-rest + webhook crypto consolidation — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Encrypt every sensitive `settings` row at rest with a libsodium pipeline rooted at `app_secret`, consolidate the v3.3.0 webhook-secret crypto onto that shared pipeline, and finish the two outstanding `lib.php` wave-1 extractions (`demo_seed`, `dhcp`).

**Architecture:** A new `lib/secret.php` module exposes a raw crypto layer — `ipam_secret_encrypt()` / `ipam_secret_decrypt()` — using `sodium_crypto_secretbox` (XSalsa20-Poly1305) under a domain-separated subkey derived from `app_secret` via keyed BLAKE2b. A settings layer (`ipam_secret_get/set`) and transparent auto-encrypt/decrypt inside `ipam_setting()` / `ipam_setting_set()` mean no call-site sweep is needed: any registry entry flagged `sensitive` is ciphertext at rest. `backup_vault_key` is explicitly excluded (it already has its own two-tier IPAMWK1 envelope). Two idempotent migrations re-encrypt existing plaintext settings rows and existing `$2W$` webhook rows. Decryption always falls back to plaintext passthrough so the pre-migration window is safe.

**Tech Stack:** PHP 8.x, libsodium (`ext-sodium`), PDO (sqlite/mysql/pgsql), PHPUnit, PHPStan L9, PHP_CodeSniffer.

**Milestone:** GitHub #83 — issues #1233, #1234, #1235, #1236, #1237, #1238, #1239, plus folded-in wave-1 finishers #909, #914, and umbrella #1045.

**Design decisions (review these before approving):**
1. **Transparent encryption in the core accessors.** `ipam_setting_set()` auto-encrypts when the registry entry has `sensitive => true`; `ipam_setting()` auto-decrypts the same set. `ipam_secret_get/set` are thin public aliases for call-site clarity. Rationale: a call-site sweep of every secret reader/writer is error-prone; transparent dispatch keyed off the registry is robust and matches the v3.30.0 storage-type dispatch pattern. The ADR-001 framing of "wrappers" is satisfied by the aliases.
2. **`backup_vault_key` is excluded** from the pipeline. It is `hidden`+`sensitive` but already carries an `IPAMWK1.` envelope under the bootstrap key (ADR-005 / `lib/vault.php`). Double-wrapping would break `ipam_vault_unwrap`. The managed-key set is "registry `sensitive => true` MINUS `backup_vault_key`", centralised in `ipam_secret_managed_keys()`.
3. **Plaintext passthrough on decrypt.** `ipam_secret_decrypt()` returns its input verbatim when the input is not an `IPAMSEC1.` envelope. This covers (a) the pre-migration window, (b) `config_key` fallback values read from plaintext `config.php`, (c) operator-set values before the next write.
4. **Envelope:** `IPAMSEC1.` || base64(nonce ‖ ciphertext). Versioned prefix mirrors `IPAMWK1.`.

```php
<?php
declare(strict_types=1);

/**
 * Simple PHP IPAM — settings-secret encrypt-at-rest pipeline (v3.31.0 #1233).
 *
 * @module secret
 *
 * Every `settings` row whose registry definition is flagged `sensitive`
 * (except `backup_vault_key`, which carries its own IPAMWK1 envelope —
 * see lib/vault.php) is stored as an IPAMSEC1 envelope. The encryption
 * key is a domain-separated BLAKE2b subkey of `app_secret` (config.php,
 * never the DB), so a stolen DB dump alone yields ciphertext only.
 *
 * Envelope format:  IPAMSEC1.<base64(nonce || ciphertext)>
 *   - IPAMSEC1.   8-byte ASCII magic + version tag
 *   - nonce       24 bytes (SODIUM_CRYPTO_SECRETBOX_NONCEBYTES), random per encrypt
 *   - ciphertext  sodium_crypto_secretbox(...), includes 16-byte Poly1305 tag
 *
 * ipam_secret_decrypt() returns non-envelope input verbatim (plaintext
 * passthrough) so the pre-migration window and config.php fallbacks are safe.
 */

const IPAM_SECRET_ENVELOPE_PREFIX = 'IPAMSEC1.';
const IPAM_SECRET_KDF_CONTEXT     = 'ipam-settings-secret-v1';

/**
 * Derive the 32-byte settings-secret key from app_secret.
 *
 * @throws \RuntimeException if app_secret is unreadable or malformed.
 */
function ipam_secret_key(): string
{
    $appSecret = ipam_app_secret();
    $raw = base64_decode($appSecret, true);
    if ($raw === false || strlen($raw) < 16) {
        throw new \RuntimeException('app_secret is missing or malformed; cannot derive settings-secret key.');
    }
    return sodium_crypto_generichash(IPAM_SECRET_KDF_CONTEXT, $raw, SODIUM_CRYPTO_SECRETBOX_KEYBYTES);
}
```

Add `require_once __DIR__ . '/lib/secret.php';` to `init.php` and `lib.php`, immediately after `lib/app_secret.php` (it depends on `ipam_app_secret()`).

```php
/** True if $value carries the IPAMSEC1 envelope prefix. */
function ipam_secret_is_envelope(string $value): bool
{
    return str_starts_with($value, IPAM_SECRET_ENVELOPE_PREFIX);
}

/** Encrypt $plaintext into an IPAMSEC1 envelope. */
function ipam_secret_encrypt(string $plaintext): string
{
    $key   = ipam_secret_key();
    $nonce = random_bytes(SODIUM_CRYPTO_SECRETBOX_NONCEBYTES);
    $cipher = sodium_crypto_secretbox($plaintext, $nonce, $key);
    sodium_memzero($key);
    return IPAM_SECRET_ENVELOPE_PREFIX . base64_encode($nonce . $cipher);
}

/**
 * Decrypt an IPAMSEC1 envelope.
 *
 * - Non-envelope input is returned verbatim (legacy plaintext passthrough).
 * - A malformed or tampered envelope returns null (no plaintext leak).
 */
function ipam_secret_decrypt(string $stored): ?string
{
    if (!ipam_secret_is_envelope($stored)) {
        return $stored;
    }
    $blob = base64_decode(substr($stored, strlen(IPAM_SECRET_ENVELOPE_PREFIX)), true);
    $minLen = SODIUM_CRYPTO_SECRETBOX_NONCEBYTES + SODIUM_CRYPTO_SECRETBOX_MACBYTES;
    if ($blob === false || strlen($blob) < $minLen) {
        return null;
    }
    $nonce  = substr($blob, 0, SODIUM_CRYPTO_SECRETBOX_NONCEBYTES);
    $cipher = substr($blob, SODIUM_CRYPTO_SECRETBOX_NONCEBYTES);
    $key    = ipam_secret_key();
    $plain  = sodium_crypto_secretbox_open($cipher, $nonce, $key);
    sodium_memzero($key);
    return $plain === false ? null : $plain;
}
```

```php
/**
 * Setting keys the encrypt-at-rest pipeline manages: every registry
 * entry flagged `sensitive`, MINUS `backup_vault_key` (which carries
 * its own IPAMWK1 envelope under the bootstrap key — see lib/vault.php;
 * double-wrapping it would break ipam_vault_unwrap()).
 *
 * @return list<string>
 */
function ipam_secret_managed_keys(): array
{
    $keys = [];
    foreach (ipam_setting_definitions() as $key => $def) {
        if (!empty($def['sensitive']) && $key !== 'backup_vault_key') {
            $keys[] = (string) $key;
        }
    }
    return $keys;
}

/** True if $key is a settings secret managed by the encrypt-at-rest pipeline. */
function ipam_secret_is_managed_key(string $key): bool
{
    return in_array($key, ipam_secret_managed_keys(), true);
}

/**
 * Read a managed settings secret, decrypted. Thin alias over ipam_setting()
 * (which already auto-decrypts) — exists for call-site clarity.
 */
function ipam_secret_get(string $key, ?string $default = null): ?string
{
    $value = ipam_setting($key, $default);
    return $value === null ? null : (string) $value;
}

/**
 * Write a managed settings secret. Thin alias over ipam_setting_set()
 * (which already auto-encrypts sensitive keys).
 */
function ipam_secret_set(PDO $db, string $key, string $value, ?int $userId = null): void
{
    ipam_setting_set($db, $key, $value, $userId);
}
```
