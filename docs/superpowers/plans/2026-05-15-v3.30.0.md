# v3.30.0 — Refactor wave 1 (lib.php decomposition + ADR-001 schema + ADR-002 prefs) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship v3.30.0 = (a) full ADR-004 wave-1 lib.php decomposition — 12 new modules under `Simple-PHP-IPAM/lib/` (utils, ip, config, db, audit, presentation, settings, user_preferences, auth, auth_password, auth_rate_limit, auth_recaptcha); (b) ADR-001 part 1 — new `setting_definitions` schema, drop `settings.type` column, dispatch refactor (no crypto); (c) ADR-002 — new `user_preferences` table + `/api/user_preference` endpoint, site_theme migrated; (d) ADR-003 foundation — `ipam_config()` accessor in `lib/config.php`, scope-bounded to extracted modules only; (e) ADR-006 — `testing/scripts/memory-audit.sh` audit script + ADR graph entity backfill; (f) milestone #56 follow-on issues Sean called out (#917-#921, #1122; verify #1120). Full milestone #56 (19 open + ~12 new ADR-derived issues).

**Architecture:**
- Phase ordering: **pre-flight** (open issues, backfill graph, branch off `dev`) → **infrastructure** (skeleton `lib-module-linter.php` so every extraction PR can run it) → **foundation extractions** (`utils.php`, `ip.php`, `config.php` — the deps base) → **schema migrations** (ADR-001 setting_definitions, ADR-002 user_preferences) so subsequent module extractions extract code that *already* targets the new schema → **mid-stack extractions** (`db.php`, `audit.php`, `presentation.php`, `settings.php`, `user_preferences.php`) → **auth four-way split** (`auth.php` + 3 specialized) → **non-ADR milestone follow-ons** (#917–#921, #1122) → **release prep + gate + deploy**.
- Every module extraction PR carries its own ADR-003 conversion: any `global $config;` in the moved functions becomes `ipam_config()` in the same commit. Net result: post-v3.30.0 the 12 extracted modules are `global $config;`-free; api.php and remaining lib.php carriers wait for #1207 (v3.31.0/v3.32.0 sweep).
- The new `lib-module-linter.php` is stood up early (Phase 1) with a skeleton rule set and grown rule-by-rule across the wave. Each extraction PR adds its module to the linter's allowed-headers list.
- The 3-driver Playwright + test_api.sh gate is the release gate. Run it locally before any push; never use CI minutes as a substitute. With migrations touching all 3 engines, expect to run the gate ≥ twice across the release.

**Tech Stack:** PHP 8.2, PHPUnit 11, PHPStan L9, PHPCS PSR-12 (project exclusions), Semgrep (project rules), Composer audit, Playwright TS, SQLite/MySQL/PostgreSQL parity. New: `lib-module-linter.php` (procedural PHP).
