# v3.25.0 Implementation Plan

> **For agentic workers:** Use superpowers:subagent-driven-development to implement task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Surface the v3.23.0 IPAMBKL1 backend to operators (picker UI + dispatch wire-up), re-home retention from schedule to destination, ship the U-series UI polish, and fix one orphan UX issue (subnet description in addresses dropdown). This is the operator-facing finale of the backup overhaul stream — backend already shipped in v3.23.0, encryption already shipped in v3.24.0.

**Architecture:** Procedural PHP under `Simple-PHP-IPAM/lib/backup.php` (existing pattern). New schema columns on `backup_destinations` (retention, default_backup_type, is_default, encryption_mode-as-default-for-runs); migration moves per-schedule retention into per-destination retention. Picker UI in `views/destination_form_*.php`. Cancel-flag column on `backup_runs`. S3 range-resume in `lib/S3Client.php`. Tests are PHPUnit + Playwright.

**Tech Stack:** PHP 8.2, PDO (sqlite/mysql/pgsql), existing IPAMBKL1 backend (v3.23.0 #824), existing IPAMBKP3 encryption (v3.24.0 #836), existing destination orchestrator (v3.22.1 #820).

## Coordination notes

- **#1076 + #849 are joined at the hip** — picker has nothing to dispatch on without #849; #849 has nothing to choose between without #1076. Land them in one commit.
- **#856 cancel reuses across #850 verify-all** — build the cancel infra once, reuse for verify-all bulk progress.
- **#1078 vs ipam_backup_notify_dispatch** — currently calls `ipam_resolve_alert_recipients()`; new helper `ipam_resolve_backup_notify_recipients()` falls back to alert helper when not overridden.
- **MySQL partial-unique-index gotcha** — `WHERE is_default = 1` only works on sqlite/pgsql. For mysql use a generated column trick: `is_default_key TINYINT GENERATED ALWAYS AS (CASE WHEN is_default=1 THEN 1 ELSE NULL END) STORED, UNIQUE KEY uq_is_default(is_default_key)`.
- **GFS retention math** — keep_hourly/daily/weekly/monthly are independent windows, not nested. A run can satisfy multiple windows (a Sunday is also that week's weekly + that month's monthly anchor).
