## Findings (assistant — sqlite test instance)

### WR-01 ⚠ FLAG (LOW) — Settings page invalid `?tab=` silently falls back to `general`

- **Where**: `Simple-PHP-IPAM/settings.php` tab-resolver branch.
- **Repro**: `GET /testing/ipam/settings.php?tab=backup` (an old name; no longer in the canonical tab list of `general/authentication/notifications/data/integrations`) returns 200 with the `general` tab's groups (`branding/display/update_check`).
- **Impact**: Operator confusion if they bookmarked an old tab URL — they'd silently land on a different tab without any "tab no longer exists" notice.
- **Recommendation**: One-line fix — render a soft "the requested tab no longer exists; showing General instead" banner, OR redirect to `?tab=general` cleanly so the URL bar reflects reality. Defer to v3.28.0 cleanup.

### WR-02 ⚠ FLAG (LOW) — `api.php` docblock advertises `X-API-Key` header but code only accepts `Authorization: Bearer`

- **Where**: `Simple-PHP-IPAM/api.php` header comment vs. its auth code.
- **Repro**: GET with `X-API-Key: <key>` → `401 "API key required. Pass via Authorization: Bearer <key> header."`
- **Impact**: Documentation/code mismatch. The error message itself is operator-actionable so the failure mode is recoverable, but anyone reading the doc-block won't expect this.
- **Recommendation**: Either (a) update the docblock to say only `Authorization: Bearer`, OR (b) accept both `X-API-Key` and `Bearer`. The OpenAPI spec served at `?resource=spec` already says Bearer only, so option (a) aligns with the live contract.
